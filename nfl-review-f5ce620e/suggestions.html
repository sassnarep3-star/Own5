S01 · Separate market-data admission from market-data discovery

Options considered

Official-only production lane

Upside: Keeps the operational evidence set tightly controlled and avoids unreviewed third-party terms.

Trade-off: The official historical record may not contain the market fields or open/close history needed for price-residual gates.

Licensed odds archive/feed

Upside: Could provide quote timestamps, event identifiers, terms clarity and open/close history in one approved source.

Trade-off: Procurement cost and the feed's exact market/jurisdiction coverage still need checking.

Isolated third-party research lane

Upside: The repository already contains historical line fields that may support exploratory comparisons if terms and lineage permit.

Trade-off: The existing game log is not official NFL data, has no separate open/close pair, and does not establish a legal/redistribution right.

Recommendation: Do not change the current production gate. Prepare a source/terms decision; if third-party data is later approved, keep it quarantined and labeled research-only until separate validation and rights checks pass.

Why this is the current recommendation: Both a third-party historical file and a live first-party operator page were found, but neither establishes an approved, timestamped open/close series for this project.

Toward admission

Written terms allow the intended storage/transformation/use; quote time, line convention, event mapping and jurisdiction are explicit; hashes and row counts reconcile.

Toward continued block

Terms are unavailable or restrictive, quote timestamps/location are missing, opening and closing are conflated, or independent row checks fail.

S11 · Normalize historical club aliases before any per-team result join

Options considered

Exact code join only

Upside: Avoids silently changing a source code when the mapping is unclear.

Trade-off: Leaves known legacy aliases unmatched and can drop club appearances from team-level calculations.

Versioned, source-backed alias map

Upside: Preserves the raw source code while mapping documented historical names to the official standings identity; tests can require 32/32 reconciliation.

Trade-off: Requires an explicit map, source for each mapping and a policy for ambiguous or retired codes.

Manual one-off replacement

Upside: Quick to patch a known case.

Trade-off: Hard to audit, easy to forget in a new desk, and can conceal future aliases.

Recommendation: Keep raw codes immutable; apply a versioned, cited alias map in a separate normalization field; fail closed on unknown codes and require club-by-club reconciliation before team-level features are published.

Why this is the current recommendation: The older e46 feed has 9 `LAR` and 9 `ARI` appearances while the official standings codes are `LA` and `AZ`; an exact join misses 18 club appearances. The newer prior desk's corrected feed demonstrates a separate code set but was not rebuilt here after the latest result delta.

Toward normalization

Each legacy-to-current mapping is documented, row counts reconcile, and every team-level result matches same-cut official standings after normalization.

Toward no mapping

A code is ambiguous, unsupported by an official identity source, or causes any club-level count/record mismatch; preserve it as unmatched and block downstream per-team use.
