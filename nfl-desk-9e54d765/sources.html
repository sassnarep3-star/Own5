Method, in one paragraph each

Line origination

Ratings are an additive offence/defence model with a home-field term, fitted by ridge regression on points scored and allowed per game over the six most recent seasons, with older seasons down-weighted. Expected margin is (offence_home − offence_away) + (defence_home − defence_away) + home field; expected total is 2·mean + both offences − both defences + home field. Probabilities use the measured residual dispersion of the same fitted window, not an assumed 13.5. Side is originated first, then total, then moneyline, and each row carries the model's own probability and a hash over the exact input object.

Walk-forward backtest

Each game is priced with parameters fitted only on games strictly before its week; the expanding window covers 1999 onward. The benchmark is the de-vigged closing moneyline (two-way proportional de-vig). Skill is 1 − Brier(model)/Brier(benchmark); the interval resamples whole season×week clusters; the Holm correction covers every family in the table.

Availability

The designation set is transcribed from the official page with its read clock. The delta between two stamped reads is published rather than a level. The ablation refits the identical model with and without three counts (Out, Doubtful, Questionable) and reports the paired difference with a cluster interval; the coefficients are estimated with a shrinkage ridge, so no fixed point penalty exists in the pipeline.

Depth

Mean offensive snap share inside a club × position group defines a usage rank. Rank 1 can contain several players. The gap from rank 1 to rank 2 is the replacement-depth proxy. Jersey numbers, draft position and salary are never read.

Reproduction

Three commands reproduce everything on this site:

python3 build_data.py   # rebuild every CSV from the committed inputs
python3 verify.py       # fail-closed check of every table, hash and link
python3 build_site.py   # render this site from the CSVs

The build is deterministic and stdlib-only. The registration hash and the hash of every input are recorded below; verify.py recomputes them and fails if any has moved.
