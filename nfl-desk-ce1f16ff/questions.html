MK-Q-01BLOCKINGWhere does a legitimate *opening* price come from for a market we originate on?Requirement 1 asks for opening and closing numbers for every originated market. The aggregator page we can read publishes an open spread and open total for some games and no open moneyline at all, so 'opening' is currently only half-fillable and the store carries the gap as a gap.The sportsbook itself, or a licensed odds feed with a timestamped open.Ask the data owner whether the site's odds history endpoint exposes a first-post timestamp per market; if not, a paid feed is the only honest route. Cost: an API plan, or one row per game left permanently blank.Opening rows recorded where the page shows them; the moneyline opening row is written with state ABSENT FROM SOURCE rather than inferred from the pre-game price.OPEN
MK-Q-02BLOCKINGWhich timestamp counts as the close for grading: kickoff, or the last pre-game quote?CLV, the demotion gate's D3 rule and every 'did we beat the market' claim depend on it. A 30-minute-early price and a kickoff price can differ by a tick on half the slate, which is larger than most of the edges on the board.No official source: this is a house convention, so it must be chosen, not discovered.Pick one, write it down, and never look back. Industry convention is kickoff; the reason to consider 'last quote before kickoff' is that kickoff quotes are sometimes pulled early on weather.Store records the capture timestamp per row and treats every current row as pre_game, never as closing.OPEN - needs a decision, not more data
MK-Q-03NON-BLOCKINGDoes the aggregator's split 'Open' cell mean the same thing for both team rows?It does not block: the number is recorded verbatim and the ambiguity is flagged (MK-F-02). It blocks *interpretation*, so no line-move statistic is published.Nobody - it is a rendering convention of one page.Compare the same game's Open cell across two capture times; if the open never moves while the pre-game does, the convention is stable enough to use.Open total stored as displayed with the o/u prefix unexplained and excluded from any computed move statistic.OPEN
MK-Q-04BLOCKINGWhich injury-report vintage is authoritative when the league report and the mirror disagree on row counts (326 vs 276 for Week 10)?Availability base rates change with the denominator, and the base rate is the one number the depth and pricing discussion leans on.The league office publishes the report; the mirror's row set is a subset by design (it drops rows without a status).Diff the two lists player by player and check whether the extra 50 official rows are all no-status rows. That is a one-hour job, and until it is done the rate carries a caveat.Both counts published per club in availability_source_diff.csv; the rate is computed on the mirror's join-able subset and labelled as such.OPEN
MK-Q-05BLOCKINGCan a player-prop bet be graded from any source this project would call official?The prop-combos division of the leaderboard, and the correlation between two players' outputs, both need graded prop outcomes. Without them the division is empty and the correlation is refused.The NFL's own play-by-play statistics, which the repository does not currently pin.Pin a play-by-play asset with a digest, as the games/injuries/snap mirrors already are, then re-run. Roughly an hour of setup, no new subscription.Prop markets captured as observations in the store; the division published as BLOCKED with this question as its reason.OPEN
MK-Q-06NON-BLOCKINGHow does the operator handle a parlay leg that pushes: void, or reduce?It changes parlay EV materially, but only for parlays containing a whole-number line. The desk's parlay division excludes pushes as void, and says so.The sportsbook's rules page - operator tier, not official NFL data.Read the posted rules for the specific bet type before any parlay is graded live; house rules differ between spreads and totals.Push leg voids the parlay; stated in grade.py and on the leaderboard page.OPEN
MK-Q-07BLOCKINGWho is allowed to promote a strategy, and can the answer be the model?The gate tables decide *whether* the evidence exists. Who acts on a yes is a governance question this build cannot answer for the project.Nobody external. This is the project's decision.Name a person and a review cadence. If no name exists, the honest setting is 'no live betting, paper only', which is what the current gates already produce.Promotion writes a recommendation, never a state change. No live staking exists.OPEN - needs a name, not data
MK-Q-08NON-BLOCKINGIs the 0.47-point measured home advantage (n=130, 95% CI -1.81 to +2.75) usable as a model constant, or must the constant stay pre-registered?It does not block the build; it blocks *tuning*. A constant estimated from the same season being backtested on is a look-ahead in disguise.Nobody publishes a true HFA; it is an estimate with an interval that contains zero.Widen the window: estimate HFA over 2021-2025 from the pinned mirror and compare with the 2026 value. If they agree within the interval, a pre-registered constant is defensible.Model uses a pre-registered 1.4-point constant and publishes the measured 2026 value beside it rather than substituting it.OPEN
