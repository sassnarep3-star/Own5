How this desk is built

  1. Capture. scripts/capture_availability.py fetches the official league injury report for each (season, week), the official weekly schedules, the official game centres, the official NFL Game Book PDF of each completed game, the official nfl.com club rosters and the official club depth charts. Every fetch records the URL, the HTTP status, the byte count, the SHA-256 of the bytes and the UTC clock time.
  2. Drift alarm. Each source kind is pinned to a row-count range. A source that leaves its range fails the build instead of publishing a blank table. Documented publisher quirks (such as a club that publishes its depth chart as an image) are listed as a known exception and are published on the flagged page.
  3. Derive. Week-over-week designation deltas, the availability graph (published rank-1 player against the official Game Book starting line-up), the designation reliability table (designation joined to the official inactive and starting lists), the per-team view and the fixture venue table are computed from the captures. A value that cannot be computed stays blank.
  4. Publish. The pages are rebuilt from the committed data by scripts/build_evidence_desk.py, which is offline and deterministic, and checked by scripts/verify_evidence_desk.py, which fails on an unsourced row, a broken internal link or a missing value that is not flagged.

What is deliberately not done

  • No injury is converted into a fixed number of points. The ablations the brief asks for need several dated captures; the machinery is in place, the sample is not yet long enough.
  • No depth order is inferred from a jersey number, an experience count or a salary. The published column order is the only depth order used.
  • No market price is published, because no operator price has been captured under a stated policy. The price columns stay blank rather than filled with an aggregator's number.
  • No value is transcribed from an image by eye.
