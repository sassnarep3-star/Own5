Methodology

The rules that make the numbers on this site checkable, written down so they can be attacked. If a rule here is wrong, the numbers it produced are wrong in a way a reader can name.

1. Nothing is inferred

Every table row ends in a source link or an explicit UNVERIFIED badge, and the check runs on the generated HTML rather than on the CSVs, so a blank that escapes the data layer is still caught. Where a value cannot be confirmed — a venue, a designation, a depth slot, a price — the cell is blank. A blank is information: it says the official page did not say.

2. The corpus is pinned, not tracked

The backtest reads a single tarball of one commit, whose SHA-256 is re-proved on every build. A new commit is a new corpus and requires a new pin, recorded with the reason. Tracking a moving branch would mean that a number published today could not be reproduced tomorrow.

3. Walk-forward, with the cutoff published

Every originated market comes from a fit that used only games strictly before the target week's first kickoff. The number of games in the fit and the cutoff date are columns on the row, so a reader does not have to trust the claim; they can check it. No market is ever fitted on its own week.

4. Rules are frozen before results exist

The fourteen rule texts, the three windows and the eight gate thresholds were written before the evaluation code ran. Changing one requires a new commit, which is the new registration. This is why the strategy table shows the rule text verbatim rather than a summary.

5. Proper scores, and intervals that respect dependence

Ranking is by Brier skill against the de-vigged close. Intervals come from a cluster bootstrap that resamples whole weeks, because games in a week share a slate and bets in a game share a result. The p-values are Holm-adjusted across every family tested, so the number of trials is priced in rather than ignored.

6. De-vig, or drop

A probability is taken from a two-sided price pair and normalised, so the vig is removed from the pair rather than assigned to one side. Where a pair does not exist, the bet is dropped and the count of dropped rows is published. No vig-free probability is ever assumed.

7. Two-sided falsification

Every strategy entry carries what would confirm it and what would refute it. A rule that can only be confirmed is not a hypothesis; it is a belief.

8. The public/private split

The site publishes derived analysis: indices, ratios, model output and links to the official page. The raw row-level captures stay in the repository rather than being re-published as a data service. That is a deliberate choice about the terms of the source data, not an oversight, and it is why every table links out rather than embedding the original rows.

9. Modelling choices are labelled as choices

Four constants are not measured: the 365-day half-life, the ridge penalties, the probit's starting sigma, and the Pythagorean exponent. Each is published with its value, applied identically to every club or every game, and flagged. A choice that is labelled can be argued with; a choice presented as a measurement cannot.

10. Reproduce it

python3 tools/season_desk_941fe39f/fetch.py --check     # prove the corpus hash
python3 tools/season_desk_941fe39f/build.py             # rebuild every table and page
python3 tools/season_desk_941fe39f/verify.py            # re-check every published row
python3 -m unittest discover -s tests -p "test_season_desk*"

No network access is needed for the rebuild: the corpus is committed, and every official capture is a JSON file with its clock time and hash.
