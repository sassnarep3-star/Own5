Verification log

What was checked, how, and what it returned.

Rules used on every row

  1. Official or flagged. A row either links to an official page, or links to the script and pinned input that computed it, or is blank and flagged. There is no fourth option.
  2. No inference. A value that is not in the source is never filled in. Missing game statuses show as pending, not as "Questionable".
  3. Tier disclosure. Official and aggregator data are labelled separately in every table.
  4. Dual-source assertion. Where the official page is parseable, the aggregator mirror must agree row for row. It currently does: 32/32 standings rows and 276/276 injury rows.
  5. Timestamps. Every fetch records URL, HTTP status, byte count, SHA-256 and UTC time in data/decision-desk/raw/provenance.json.

The sign-convention check that changed the answer

The first backtest of the injury metric used margin + spread as the against-the-spread residual, which treats the spread as a handicap on the home team. The pinned source actually stores the expected home margin (positive = home favoured). With the wrong sign the strategy looked like 57.4% ATS; with the correct sign it is 51.4% (p = 1.0). The erroneous run is preserved in the claim table, and suggestion S02 adds a regression test so it cannot recur silently.
